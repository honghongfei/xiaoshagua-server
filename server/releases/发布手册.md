# 小傻瓜云更新 · 发布操作手册

> 面向：把"打好的客户端新版"上传到服务器、对玩家发布更新（全量 / 增量 / 强制更新 / 强制修复）。
> 适配你的部署：Ubuntu 云服 `/srv/xsg`、`pm2` 进程 `xsg-server`、node 端口 `3000`、对外经 Caddy `wss://xgshx.duckdns.org:8443`。

---

## 0. 三个位置先记牢

| 角色 | 位置 | 作用 |
| --- | --- | --- |
| 开发机（Windows） | 源码 `D:\agentsxiaoshagua\xiaoshagua`；产物 `D:\agentsxiaoshagua\xiaoshagua-releases` | 改版本、打包、生成 zip/manifest/patch |
| 服务器（Ubuntu） | 代码 `/srv/xsg`，服务端 `/srv/xsg/server`，**发布目录 `/srv/xsg/server/releases`** | 对外下发更新 |
| 客户端 | 标题画面「检查更新」面板 | 拉 `https://xgshx.duckdns.org:8443/update/...`（经 Caddy 反代到 node:3000） |

> 客户端地址自动推导：`XdRs_Online_Net.serverUrl = wss://xgshx.duckdns.org:8443` → 更新走 `https://xgshx.duckdns.org:8443/update/`（`wss://`→`https://`，沿用 8443 端口）。
> Caddy 反代：按 `server/DEPLOY.md` §4 的 `reverse_proxy localhost:3000`（站点根 catch-all），`/update/*` 会**自动**代理到 node:3000，无需额外规则。仅当你的 Caddyfile 用了路径匹配、只代理了 socket.io 时，才需补一条 `/update/*` 反代到 `localhost:3000`。

## 1. 最常用：发布一个全量新版（5 步）

### 步骤 1 · 改版本号（唯一可信源）
编辑 `D:\agentsxiaoshagua\xiaoshagua\package.json` 的 `window.title`，把版本号抬高，例如 `... V1.5.3` → `... V1.5.4`。

### 步骤 2 · 开发机打包
```powershell
cd D:\agentsxiaoshagua\xiaoshagua
PowerShell -ExecutionPolicy Bypass -File tools\build_release.ps1
```
产出到 `D:\agentsxiaoshagua\xiaoshagua-releases\`：
- `xiaoshagua-v1.5.4-test.zip`（整包）
- `manifest.json`（含 latest / full / sha256 / size）
- `files-1.5.4.json`（每文件哈希，**增量 diff 用，留着别删**）

### 步骤 3 · 上传产物到服务器（你问的重点，见 §2）
把 `xiaoshagua-releases\` 里的 **zip + manifest.json**（做增量再加 `patch-*.zip` + `patch-*.meta.json`）传到服务器一个中转目录，例如 `/srv/xsg/_incoming/`。

### 步骤 4 · 在服务器上"发布"（合并进 releases）
SSH 进服务器：
```bash
cd /srv/xsg/server
npm run publish:release -- /srv/xsg/_incoming
```
它会：复制整包 + 所有 patch 包 → 合并出对外 `releases/manifest.json`（**保留你的强制更新门槛 minVersion**、累积 `patches[]`）。

### 步骤 5 · 验证
```bash
# 服务器本机(源站)
curl -s http://127.0.0.1:3000/update/manifest | head
# 外网经 Caddy(客户端真实走的地址)
curl -s https://xgshx.duckdns.org:8443/update/manifest | head
```
两个都看到 `"latest":"1.5.4"` 即成功。玩家下次启动 / 点「检查更新」就能拉到。

## 2. 怎么把产物上传到服务器（三选一）

> 目标：把开发机 `D:\agentsxiaoshagua\xiaoshagua-releases\` 的内容传到服务器 `/srv/xsg/_incoming/`。
> 先在服务器建中转目录：`mkdir -p /srv/xsg/_incoming`

### 方式 A · scp（Windows 10/11 自带，最简单）
开发机 PowerShell：
```powershell
scp -r "D:\agentsxiaoshagua\xiaoshagua-releases\*" <用户名>@<服务器IP>:/srv/xsg/_incoming/
```
（首次会让你确认指纹并输入服务器密码。）

### 方式 B · WinSCP（图形界面，怕命令行用这个）
1. 下载 WinSCP，新建会话：协议 SFTP、主机 `<服务器IP>`、端口 22、用户名/密码。
2. 左侧进 `D:\agentsxiaoshagua\xiaoshagua-releases`，右侧进 `/srv/xsg/_incoming`。
3. 把 zip + manifest.json（+ patch 文件）拖过去。

### 方式 C · rsync（量大/常发，增量快，需服务器有 rsync）
开发机用 WSL 或 Git-Bash：
```bash
rsync -avz --progress /d/agentsxiaoshagua/xiaoshagua-releases/ <用户名>@<服务器IP>:/srv/xsg/_incoming/
```

> 重要：**publish 要在服务器上跑**（而不是开发机），这样 minVersion 才会读取并保留服务器现网值。开发机上跑 publish 只会写到开发机本地，不影响线上。

## 3. 发布增量更新（省玩家流量，可选）

前提：服务器已有"被升级版本"和"新版本"，且开发机 `xiaoshagua-releases\` 留着各版本的 `files-<ver>.json`。

```powershell
# 1) 先按 §1 步骤 1-2 改版本号 + build_release.ps1（生成新版 files-<新版>.json）
# 2) 为最近 N 个旧版本批量生成到新版的增量包：
cd D:\agentsxiaoshagua\xiaoshagua
PowerShell -ExecutionPolicy Bypass -File tools\make_patches_all.ps1 -Keep 5
#   先看计划不实际生成可加 -DryRun
```
产出 `patch-<旧>-to-<新>.zip` + `patch-<旧>-to-<新>.meta.json`。
然后照 §2 把 **patch 包 + meta + 整包 + manifest.json** 一起上传，再 §4 `publish:release`（会自动把 patch 合并进 manifest）。

> 客户端逻辑：本地版本能匹配到某条 `from→latest` 就走增量，匹配不到自动回退整包。所以**整包永远要发**，patch 是锦上添花。

## 4. 强制更新门槛（minVersion）

- 默认 `minVersion = 0.0.0`：不拦任何人。
- 要"低于某版本必须更新才能登录"：在**服务器**发布时指定，例如强制 ≥ 1.5.4：
```bash
cd /srv/xsg/server
XSG_MIN_VERSION=1.5.4 npm run publish:release -- /srv/xsg/_incoming
```
- 取消强制：发布时设回 `XSG_MIN_VERSION=0.0.0`（否则会沿用现网较高值，不会被普通发布清空）。
- 生效：服务端 15 秒缓存，最多 15 秒后对低版本登录返回 `VERSION_TOO_LOW`，客户端弹强制更新窗。

---

## 5. 玩家侧的"强制修复"（不用你操作）

玩家在「检查更新」面板点「强制修复」→ 重新下载整包并强制覆盖所有文件（存档保留），用于修复损坏/缺失/被改的文件。**复用现有整包，不需要你额外发布任何东西**。

---

## 6. 回滚

想退回旧版：编辑服务器 `/srv/xsg/server/releases/manifest.json`，把 `latest` 和 `full` 指回旧版 zip（旧 zip 只要还在 releases 目录就行），`patches` 删掉或留空。15 秒内生效。

---

## 7. 常见坑

- **必须在服务器跑 publish**：否则 minVersion 不会保留、产物也没真正上线。
- **整包永远要发**：增量只是优化，缺整包会导致匹配不到 patch 的玩家无法更新。
- **`files-<ver>.json` 要在开发机留档**：增量 diff 靠它对比，删了就只能发全量。
- **安全组放行 8443**（wss/HTTPS，客户端实际连这个）；3000 可只对内网，由 Caddy 反代。
- **Caddy 必须代理 /update/**：`reverse_proxy localhost:3000` catch-all 即自动覆盖；若只代理了 socket.io 路径，云更新会 404，需补 `/update/*` 反代到 `localhost:3000`。
- **公网 IP 变了**：要改客户端 `XdRs_Online_Net.serverUrl` 并重发客户端。
- **校验**：客户端下载后会校验 SHA256，manifest 里的 `full.sha256` 必须与实际 zip 一致（build 脚本自动算，别手改）。

## 8. 一页速查

```text
改版本号(package.json title)
  → build_release.ps1                      (开发机, 产出 zip+manifest+files-*.json)
  → [可选] make_patches_all.ps1 -Keep 5    (开发机, 产出 patch+meta)
  → scp/WinSCP/rsync 上传到 /srv/xsg/_incoming   (开发机 → 服务器)
  → cd /srv/xsg/server && npm run publish:release -- /srv/xsg/_incoming   (服务器)
  → curl https://xgshx.duckdns.org:8443/update/manifest 验证(外网经 Caddy)
  → 玩家「检查更新」即可
```

## 9. 一键发布脚本（推荐）

`tools/deploy_release.ps1` 把上面 1–5 步合成一条命令（打包 → 增量 → 上传 → 服务器 publish → 验证）。**脚本不存任何密码。**

一次性配置（只做一次，输一次服务器密码装公钥，之后免密）：
```powershell
PowerShell -ExecutionPolicy Bypass -File tools\deploy_release.ps1 -SetupKey
```

日常发布：
```powershell
PowerShell -ExecutionPolicy Bypass -File tools\deploy_release.ps1
```

带强制更新门槛：
```powershell
PowerShell -ExecutionPolicy Bypass -File tools\deploy_release.ps1 -MinVersion 1.5.4
```

常用开关：
- `-SkipPatches`：只发全量，不生成/上传增量包
- `-SkipBuild`：复用已打好的 `xiaoshagua-releases\` 产物，不重新打包
- `-Keep 5`：增量覆盖最近 5 个旧版本
- `-ServerIP / -User / -RemoteServerDir`：覆盖默认（默认 `root@8.220.187.68`，发布目录 `/srv/xsg/server`）

> 安全：脚本不含密码；强烈建议先 `-SetupKey` 改用密钥登录，并尽快修改在聊天里暴露过的 root 密码。
